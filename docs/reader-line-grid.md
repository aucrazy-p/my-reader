# 阅读页整行排版约定

> 2026-11-14 确认。适用于 `frontend/src/views/ReaderView.vue` 的纵向滚动阅读模式。
> 背景：网络源小说上/下边界出现半截行；`9f6edee` 的 JS 行级吸附只修了顶部的一部分，底部仍会截断。

## 目标

纵向滚动时视口上、下边界都不得出现半截行；**窗口可任意拉伸**，设置项（页宽、边距、字号、行高、字体）不受限制；F12 纯净无边框与 `resizable` 行为不变。

## 约定（实现与维护必须遵守）

1. **窗口尺寸自由**：不得锁定、量化或吸附窗口高度。要对齐的是「正文可视区的有效高度」，不是窗口。
2. **零头留白**：有效高度 = `floor(可用高度 / 行高) × 行高`；不足一行的零头 `r`（`0 ≤ r < 行高`）吸收进 `.reader-view.viewport-inset-mode` 的 `padding-bottom`。该层 `overflow: hidden`，正文永远滚不进这段留白，不产生黑边。
3. **零头只加底部**，不分摊到顶部——顶部必须保持整行起点，否则顶部又会偏。
4. **按真实行矩形吸附**：用 `Range.getClientRects()` 取视口附近的真实文字行，由「让任意行沿落到视口顶边/底边」生成位移候选（限一行内），再按滚动后上/下边界各切掉多少行高评分（顶边权重更高），选最完整的一个；不比原地更好就不动。禁止再用 `baseTop + n × lineHeight` 这类全局均匀行网格假设（段距、标题、图片都会破坏网格，实测残留 3.5～8.2px 半截）。章节开头顶部是标题区时靠底边候选兜底。
5. **边缘不跳过**：吸附目标 `clamp` 到 `[0, maxScroll]`。唯一例外是 `scrollTop === 0`（首屏顶部本就完整，避免把章节标题滚掉）；其余含首屏附近与末屏区域一律照常吸附。
6. **行高按当前视口内的正文元素取** `computed lineHeight`，不取文档中第一个匹配元素（连续阅读多章节、EPUB 会算错基准）。
7. **重算时机**：挂载、`resize`、`APP_VIEWPORT_CHANGE_EVENT`、字号/行高/字体/上下左右边距/纯净模式/听书面板高度/章节内容变化。计算时先扣除滚动容器自身的 `padding-bottom`（听书面板会让内容可视区变矮）。
8. **左右分页模式不参与**：它自带整页机制，零头必须为 0，吸附函数直接返回。
9. **吸附手感**：只作用于纵向滚动；单次位移上限 1 行，找不到行矩形不吸附；保留 140ms debounce、320ms `isSnapping` 防抖与原生 smooth，避免和用户滚动抢位置。

## 依据

底部边界 = `scrollTop + clientHeight`。JS 只能改 `scrollTop`；只要 `clientHeight` 不是行高整数倍，底边就必然落在某一行中间，靠吸附消除不了。实测：视口 800px 时 `clientHeight = 752`、行高 32.4px、`752 mod 32.4 = 6.8`，首屏底部被切 21.6px；把视口调到 778px（≈24 整行）后首屏底部归零，反证了根因。

## 验证口径

- `npm run build`（vue-tsc + vite build）、`npm test`。
- Playwright 打开真实阅读页（Vite dev server + Edge），注入 `reader-last-session` 模拟网络源章节，用 `Range.getClientRects()` 逐行矩形与容器上/下边界比对：任意滚动位置的 `topCut` / `bottomCut` 应 ≈ 0；真实滚轮连滚后位置稳定、无二次漂移。
- 回归基线：视口 800px 首屏（原切 21.6px）、`scrollTop = 12`（原切 9.6px）、若干中段随机位置、826px 视口、`scrollTop` 接近 `maxScroll`。

## 已知残留（2026-11-14 实测，未解决）

- **首屏 `scrollTop = 0` 在部分窗口高度仍有底部半截行**：680px 视口 14.1px、740px 21.3px、920px 3.2px、1000px 13.9px；860px 中段 6.1px、920px 中段 9.7px。800/860px 首屏为 0，800px 全点位（含 12 / 48.6 / 1000.3 / 1700.6 / 2600.4 / 接近底部）均为 0/0。
- **根因**：段距 `0.2em`(3.6px) 与章节标题让正文行不是均匀行网格，「视口高度取行高整数倍」只在部分高度恰好成立；首屏又不能靠滚动吸附修正（会把章节标题滚出视口）。
- **已试并回退**：把正文首行补到整行位置（`--reader-line-head-inset`）→ 800px 首屏反而从 0 变成 20.1px，因段距累积使网格假设不成立，已完整撤销。
- **下一步候选路线（需重新讨论，勿继续打补丁）**：
  1. 按首屏真实行矩形动态选 remainder（在 0～行高内评分，让底边落在行间空隙），而非固定 `H mod 行高`；
  2. 允许首屏小幅下滚吸附，接受章节标题轻微上移；
  3. 段距归一为行高整数倍（会改变排版设置，需产品确认）。

## 禁止

- 恢复 `scroll-snap-type: y mandatory`：长段落中段会被硬拉回段首。
- 用全局行网格公式做吸附，或把段距强行改成行高整数倍（会破坏排版设置）。
- 锁死窗口高度、把零头做成黑边、用渐隐遮罩遮住半截行当作「修好」。
